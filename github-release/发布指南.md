# LogParser 通过 GitHub Releases 发布更新（指南）

**仓库**：`WenDiDan/log-parser`
**当前版本**：`1.0.7`（待发布）｜ 已发布：`v1.0.6`
**升级源直链**：
```
https://github.com/WenDiDan/log-parser/releases/latest/download/version.json
```

本目录是**待上传到 GitHub Releases 的发布包**，包含：
- `version.json` —— 升级清单（`url` 用相对路径 `LogParser.exe`，自动基于本文件所在目录拼接 exe 地址）
- `LogParser.exe` —— 当前版本安装包（1.0.7，约 48MB）

---

## 一、为什么用 `latest` 而不是固定 Tag

| 写法 | 示例 | 问题 |
|---|---|---|
| 固定 Tag | `.../releases/download/v1.0.6/version.json` | ❌ 该 Release 的清单**永远写着 1.0.6**，客户端升到 1.0.7 后再去问它，永远看不到更新，**升级链断裂** |
| **`latest`（现行）** | `.../releases/latest/download/version.json` | ✅ 永远指向最新发布的 Release，一劳永逸 |

GitHub 会对 `latest` 做 302 重定向，程序的 urllib 能自动跟随。
相对 `url: LogParser.exe` 会拼成 `.../releases/latest/download/LogParser.exe`，同样是合法直链。

> **好处**：用 `latest` 后，以后发新版**客户端完全不用改升级源**，发完即自动可检测。

## 二、发布（推荐用 `发布.bat` 一键完成）

项目根目录的 `发布.bat` 已内置仓库名，双击即可：

```
发布.bat
```

它会自动：检测 `gh` → 检测登录 → 读 `version.json` 版本号 → 创建/追加 Release → 上传 `LogParser.exe` + `version.json`。

> 已加 `--clobber`：对**已存在的 Tag** 重新发布时会覆盖同名资产，方便重打 exe 后覆盖上传。

### 手动发布（备选）
```powershell
gh release create v1.0.7 \
  "E:\WorkBuddy\log-parser\github-release\LogParser.exe" \
  "E:\WorkBuddy\log-parser\github-release\version.json" \
  --repo WenDiDan/log-parser --title "v1.0.7" --notes "升级至 v1.0.7"
```
若 Tag 已存在，改用覆盖上传：
```powershell
gh release upload v1.0.7 `
  "E:\WorkBuddy\log-parser\github-release\LogParser.exe" `
  "E:\WorkBuddy\log-parser\github-release\version.json" `
  --repo WenDiDan/log-parser --clobber
```

> ⚠️ **不要用网页拖拽上传**：GitHub 网页拖拽硬限 25MB，48MB 的 exe 会报 `Yowza, that's a big file...`。
> Release 资产真实上限是 2GB，用 `gh` CLI 或 API 上传即可绕过。

## 三、客户端升级源配置

### 多源容灾（1.0.7 起支持）
程序支持**配置多个升级源**，**每行一个**，按顺序尝试，**第一个可用的生效**，某源不可用时自动回落下一个。

菜单 **帮助 → 升级源设置…** 打开多行编辑框，例如：
```
https://gitee.com/<你的用户名>/<仓库>/raw/main/LogParser/version.json
https://github.com/WenDiDan/log-parser/releases/latest/download/version.json
```
保存后按顺序尝试：国内走 Gitee（快），Gitee 不通自动回落 GitHub。
全部失败时才报错，并列出每个源的具体错误，方便排查。

按钮说明：**恢复默认** = 还原为内置候选列表；**保存** = 写入配置 `~/.logparser/config.json`。

> ⚠️ **Gitee 源的硬性限制**：Gitee 公开仓库 raw 文件**大于 10MB 需鉴权**（官方规定），
> 48MB 的 exe 匿名拉不到。所以：
> - `version.json`（1KB）放 Gitee raw ✅ 国内 CDN 秒开
> - **exe 必须放 Gitee 发行版**（单附件上限 100MB，48MB 没问题），
>   且清单里 `url` 要写**绝对直链**，如
>   `https://gitee.com/<用户名>/<仓库>/releases/download/v1.0.7/LogParser.exe`
> - 若写成相对路径 `LogParser.exe`，会拼到 raw 地址上导致下载失败

未填写的占位符地址（含 `<` `>`）会被自动跳过，不会拖慢检查。

### 新客户端（默认已内置，开箱即用）
内置候选源（按顺序）：
```
https://gitee.com/WenDiDan/log-parser/raw/main/LogParser/version.json        ← 国内快，优先
https://github.com/WenDiDan/log-parser/releases/latest/download/version.json    ← 回落
```
新打包的程序**无需任何配置**，启动即自动检测。

> ⚠️ **发版时两边都要传 exe**：程序取到哪个清单，就用那个清单里的 exe 地址。
> 若只在 GitHub 传了 exe、Gitee 发行版还没传，客户端走 Gitee 清单会下载失败。
> 要么两边都传，要么临时把没准备好的源从升级源列表里删掉。
> Gitee 侧的搭建步骤见 `..\gitee-release\发布指南.md`。

另外代码里有**旧源自动迁移**（`LEGACY_MANIFESTS`）：配置中若是以下地址，启动时会自动切到上面的 `latest` 源，不用逐台手改：
- `\\192.168.250.24\软件\LogParser\version.json`（已废弃的共享服务器）
- `https://github.com/WenDiDan/log-parser/releases/download/v1.0.6/version.json`（早期固定 Tag 写法）

### 老客户端（1.0.6 及更早，需手动设一次）
1. 打开 LogParser → 菜单 **帮助 → 升级源设置…**
2. 填入：
   ```
   https://github.com/WenDiDan/log-parser/releases/latest/download/version.json
   ```
3. 保存。之后**永久生效**——以后发任何新版都不用再改。

> 提示：填的是 **version.json 的地址**，不是 exe 的；exe 由清单里 `url` 字段的相对路径自动定位。
> 所以**两个文件必须在同一个 Release**（同目录），否则拼不出正确地址。

## 四、以后发新版本（如 1.0.8）

1. 改三处版本号（保持一致）：
   - `LogParser.py` 的 `APP_VERSION`
   - `version.txt` 的 `filevers`/`prodvers` 与 `FileVersion`/`ProductVersion`
   - 根目录 `version.json` 和本目录 `version.json` 的 `"version"`，并更新 `notes`
2. 重打包：`打包.bat`（或 PyInstaller 命令），产物在 `dist/LogParser.exe`。
3. 把新 `dist/LogParser.exe` 复制到本目录，覆盖旧 exe。
4. 跑 `发布.bat` → 自动建 `v1.0.8` Release 并上传。
5. **客户端无需任何改动**，启动后自动检测到 1.0.8 并提示升级。

## 五、注意事项

- exe 约 48MB（matplotlib 统计图表依赖，是真实功能），GitHub Releases 单文件上限 2GB，无压力。
- 国内访问 `github.com` / `release-assets.githubusercontent.com` 偶有波动；程序用 urllib 直接拉、带重试，通常可用。
  若现场网络极差，再迁到腾讯云 COS / 阿里云 OSS 对象存储。
- 升级源**不要开鉴权**：程序用 urllib 直接 GET，带不了 token，公开读即可。
- 清单与 exe 必须同 Release 同目录，否则相对 `url` 拼不出正确地址。
- `latest` 指向的是**最新发布**的 Release（非草稿、非预发布）。若不小心把旧版本设为最新，客户端会误判——发版时确认 Release 已 Publish 且是最新版。
- 给 Windows 写 `.bat` 一律**纯 ASCII**，且 `if`/`for` 代码块内的 echo 文案**严禁出现半角括号** `()`，
  否则 cmd 会解析崩溃（报 `此时不应有 ...`）。
