# Gitee 升级源配置指南

**仓库**：`https://gitee.com/WenDiDan/log-parser`
**清单地址**（程序会请求它）：
```
https://gitee.com/WenDiDan/log-parser/raw/main/LogParser/version.json
```

---

## 一、为什么这样拆（重要）

Gitee 官方规定：**公开仓库 raw 文件大于 10MB 需鉴权**（需私人令牌 `curl --oauth2-bearer`）。
程序的 `urllib` 是匿名请求，**48MB 的 exe 用 raw 直链拉不到，升级会直接失败**。

所以必须拆开：

| 文件 | 大小 | 放哪里 | 说明 |
|---|---|---|---|
| `version.json` | 1KB | Gitee **仓库 raw** | 远低于 10MB，国内 CDN 秒开；且是每次启动都请求的高频操作，收益最大 |
| `LogParser.exe` | 48MB | Gitee **发行版附件** | 单附件上限 100MB（GVP 200MB），48MB 没问题 |

> ⚠️ 清单里的 `url` **必须写绝对直链**指向发行版附件。
> 若写成相对路径 `LogParser.exe`，会拼成
> `https://gitee.com/WenDiDan/log-parser/raw/main/LogParser/LogParser.exe`
> —— 正好撞上 10MB 鉴权，下载失败。

---

## 二、首次搭建（一次性）

1. 在 Gitee 建**公开**仓库 `log-parser`（必须公开，否则 raw 需鉴权）。
2. 把本目录下的 `LogParser/version.json` 提交到仓库的 `LogParser/version.json` 路径：
   ```
   LogParser/
   └── version.json      ← 就是这个文件
   ```
   提交后访问确认能看到内容：
   `https://gitee.com/WenDiDan/log-parser/raw/main/LogParser/version.json`
3. 仓库 → **发行版** → **新建发行版**：
   - 版本号/Tag：`v1.0.7`
   - 附件：上传 `LogParser.exe`（48MB，网页上传即可，未超 100MB）
   - 发布
4. 上传后附件下载地址应为：
   ```
   https://gitee.com/WenDiDan/log-parser/releases/download/v1.0.7/LogParser.exe
   ```
   （Gitee 官方格式：`/{namespace}/{repo}/releases/download/{git_tag}/{文件名}`）

## 三、程序侧（已内置，无需配置）

1.0.7 起程序内置多源候选，按顺序尝试、首个可用者生效：
```
1. https://gitee.com/WenDiDan/log-parser/raw/main/LogParser/version.json     ← 国内快
2. https://github.com/WenDiDan/log-parser/releases/latest/download/version.json  ← 回落
```
Gitee 通就走 Gitee，Gitee 挂了自动回落 GitHub，全挂才报错（并列出每个源的具体错误）。

也可在 **帮助 → 升级源设置…** 里手动调整（每行一个源，支持「恢复默认」）。

## 四、一键发布（推荐）

在项目根目录双击 **`发布_Gitee.bat`**，或在命令行运行：
```bat
python publish_gitee.py
```

它自动完成四步（幂等，可反复发布同一版本）：
1. 若已存在同名发行版，先删除
2. 创建发行版
3. 上传 `dist/LogParser.exe` 作为发行版附件（48MB，需十几秒到几分钟）
4. 更新仓库内 `LogParser/version.json`（程序检查更新读的就是它）

### 首次需要 Gitee 私人令牌（二选一）
```bat
set GITEE_TOKEN=你的令牌
```
或把令牌写入项目根目录的 `gitee_token.txt`（**不要提交到仓库**）。

令牌获取：https://gitee.com/profile/personal_access_tokens

> 依赖 Python：脚本依次查找 `.venv` → WorkBuddy 内置 Python → `py -3` → `python`。
> 核心逻辑在 `publish_gitee.py`，纯标准库，无需安装任何包。
> 底层调用的是 Gitee OpenAPI v5：
> `POST /v5/repos/{owner}/{repo}/releases` 建发行版、
> `POST /v5/repos/{owner}/{repo}/releases/{id}/attach_files` 传附件（multipart）、
> `POST /v5/repos/{owner}/{repo}/contents/{path}` 更新清单文件。

## 五、以后发新版本（如 1.0.8）

1. 改版本号（三处 + 两份清单）：
   - `LogParser.py` 的 `APP_VERSION`
   - `version.txt` 的 `filevers`/`prodvers` 与 `FileVersion`/`ProductVersion`
   - 根 `version.json`、`dist/version.json`
   - `github-release/version.json`（GitHub 侧）
   - 本目录 `LogParser/version.json`（Gitee 侧，**url 里的 Tag 也要改成 v1.0.8**）
2. 重打包：`打包.bat`
3. 分别发布：
   ```bat
   发布_Gitee.bat    :: Gitee 侧（建发行版 + 传 exe + 更新清单）
   发布.bat          :: GitHub 侧
   ```

> ⚠️ **两边都要传 exe**：程序取到哪个清单就用哪个清单里的 exe 地址。
> 若只在 GitHub 传了 exe，而 Gitee 清单仍指向 Gitee 发行版（尚未上传），会下载失败。
> 所以发版要么两边都传，要么临时把没准备好的那个源从升级源列表里去掉。

---

## 六、注意事项

- 仓库必须**公开**，否则 raw 需鉴权，程序匿名拉不到。
- Gitee raw 会被重定向到 `raw.giteeusercontent.com`，程序 urllib 会自动跟随；服务端有 60~300 秒缓存，
  刚提交的版本清单可能略有延迟，属正常现象。
- Gitee 发行版单附件 100MB、仓库总附件 1GB；48MB 的 exe 可放心使用。
- Gitee 发行版也支持 `/releases/latest`（自动跳最新），但清单里建议用固定 Tag 的 exe 地址，避免取到中间态。

## 七、离线 / 无网现场：用本地文件源升级

**适用场景**：现场设备无外网（连不上 Gitee / GitHub），但仍想用自带的「检查更新」机制升级。
做法：把升级包放本地目录 / U 盘 / 内网共享，让升级源**第 1 行**指向该目录的 `version.json`。

### 升级源三层结构
```
1. 本地文件路径（离线，优先）   ← 本节讲的
2. Gitee raw 清单（联网优先）    ← 见上
3. GitHub latest（联网回落）     ← 见《发布指南》GitHub 版
```
无网自动落本地源；有网自动走 Gitee/GitHub——同一份客户端两种环境都通。

### 离线升级包（同目录两文件）
```
D:\LogParser_update\
├── version.json      ← 清单，url 用【相对】 "LogParser.exe"
└── LogParser.exe     ← 与清单同目录
```

`version.json` 模板（**注意是相对路径**）：
```json
{
  "version": "1.0.8",
  "url": "LogParser.exe",
  "notes": "离线升级包：把本目录作为升级源第1行指向 version.json 即可。"
}
```

### 现场客户端配置（每台一次，或批量预置）
1. **帮助 → 升级源设置…**，把第 1 行改成离线包里 `version.json` 的实际路径：
   ```
   D:\LogParser_update\version.json
   ```
   （U 盘盘符、UNC `\\server\share\LogParser\version.json` 均可）
2. 保存 → **检查更新**：无网时读本地清单，版本更高则下载同目录 exe 完成替换。
3. 批量部署：把写好的 `config.json`（`update_manifests[0]` 指向约定更新目录）随 U 盘发到现场机，
   `C:\Users\<用户名>\.logparser\config.json`，开机即生效，之后只更新目录里的两文件即可。

### 关键区分（别混）
| 源类型 | `url` 写法 | 原因 |
|---|---|---|
| 本地 / 离线 | **相对** `"LogParser.exe"` | 程序按 `os.path.join(清单目录, url)` 拼，换盘符通用 |
| Gitee / GitHub | **绝对直链** | Web 地址，相对写法会拼到 raw 撞 10MB 鉴权 |

> 离线清单 url 用相对、Web 清单 url 用绝对——规则不同，切勿互相套用。
> 更完整的现场步骤见 `离线升级说明.md`。
