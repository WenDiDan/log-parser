# LogParser · 设备日志解析器

针对产线设备（超声终焊、扫码枪等）按 **设备 / 模块 / 日期_班次** 组织的 txt 日志，
做目录树浏览、关键字检索、异常筛出、结构化查看与导出的小工具。

单个 exe，双击即用，不写注册表、不装依赖；支持从 Gitee / GitHub 多源自升级。

---

## 快速开始

双击 **`启动.bat`** 即可。脚本会用 `_find_python.bat` 找一个**带 tkinter** 的 Python
来跑 `LogParser.py`，找不到会给出明确提示。

命令行等价写法：

```bat
python LogParser.py
```

依赖：Python 3 标准库 + tkinter。**统计图是自绘的**，不依赖 matplotlib
（早期版本因为它体积多了约六成，现已移除并在 `build_args.py` 里显式排除）。

可选装 **Pillow**：只用来把 `app.ico` 以高分辨率喂给 `iconphoto()`，让标题栏 /
任务栏 / Alt-Tab 的图标不发虚。没装也能正常运行，只是图标回落到 `iconbitmap`
的模糊版本。`启动.bat` 因此**只要求 tkinter**，不强制 Pillow。

## 日志目录结构

程序按目录名推断「设备」和「模块」，按文件名推断「日期」和「班次」：

```
<根目录>/
├── Ultrasonicwelding2/          ← 设备
│   ├── WCF/                     ← 模块
│   │   ├── 2026-07-20_09_12.txt ← 日期_班次
│   │   └── 2026-07-20_13_16.txt
│   └── sys/
│       └── 2026-07-20_09_12.txt
└── 1号托盘扫码枪/                ← 单层目录也可：设备与模块同名
    └── 2026-07-24_09_12.txt     ← 文件直接挂在设备节点下
```

- 文件名以 `YYYY-MM-DD` 开头就能识别日期，`_HH_MM` 后缀作为班次；
  **认不出日期的文件仍会被搜索**，只是不参与按日期的整文件过滤。
- 行内时间戳格式为 `[2026-07-20 11:14:05]正文`。没有时间戳的行照常显示，
  时间列显示为 `—`；它们不受「日期范围」筛选影响（无法判断归属）。

## 功能

| 功能 | 说明 |
|---|---|
| 目录树浏览 | 设备 / 模块 / 文件三级，支持勾选与右键，勾选父节点即包含其下全部文件 |
| 刷新目录 | 日志持续写入时，`Ctrl+R` 或工具栏「刷新」增量同步新文件，保留原有勾选 |
| 关键字检索 | 多关键字（任选其一）、`正则`、`全部匹配`（AND）、`仅异常` |
| 日期筛选 | 按日期范围过滤，先按**文件名日期**跳过整天无关的文件，再逐行核对时间戳 |
| 结果上限 | 2000 ~ 100000 或「不限制」，达到上限会提示已截断 |
| 排序 | 点列头切换升降序，十几万条也在几秒内完成，期间界面可继续操作 |
| 结果内二次筛选 | 就地缩小范围，只隐藏不匹配的行，原始结果与导出内容不受影响 |
| 详情窗口 | JSON 自动美化、`Key: Val` 结构化、命中关键词高亮、上一条/下一条翻页 |
| 查看上下文 | 展开该行在原文件中的前后 20 行，并**自动定位**到命中行（黄底标记） |
| 统计 | 模块条数、按小时分布、异常率、峰值时段 |
| 导出 | CSV / TXT |
| 自动升级 | 多升级源并发探测，发现新版本后右上角出现按钮，点击原地升级 |

### 快捷键

| 按键 | 作用 |
|---|---|
| `Ctrl+O` | 打开日志目录 |
| `Ctrl+R` | 刷新目录（读取新增日志） |
| `F5` / `Ctrl+Enter` | 开始搜索 |
| `Esc` | 停止搜索 / 关闭弹窗 |
| `Ctrl+F` | 跳到「在结果中筛选」 |
| `Ctrl+L` | 清空结果 |
| `Ctrl+E` | 导出 CSV |
| `←` / `→` | 详情窗口里上一条 / 下一条 |

配置文件位于 `%USERPROFILE%\.logparser\config.json`，记录上次目录、搜索条件、
升级源等；菜单「工具箱 → 导出/导入配置」可整体搬迁到别的机器。

## 打包与发布

全部收敛在**发布工具**里，双击 **`发布工具.bat`**（用 `pythonw` 启动，不留控制台窗口）。

工具的四个步骤：

```
1 发布前检查    版本一致性 / 打包产物版本 / git 工作区是否干净、标签是否已打
2 打包          PyInstaller 打成单文件 dist\LogParser.exe
3 发布          推送到 Gitee / GitHub Releases（可并行）
4 发布后自检    校验线上清单与文件是否可下载
```

- **只有一处版本源**：`LogParser.py` 的 `APP_VERSION`。改它之后用工具里的
  **「升级版本…」** 一键同步 `version.txt` 与各 `version.json`，不要手改。
- 用 **`check_version.py`** 校验所有清单是否一致（退出码非 0 表示不一致）。
- 发布流程的细节（为什么用 `latest`、多源容灾、注意事项）见
  [`github-release/发布指南.md`](github-release/发布指南.md)。

## 自测

```bat
python _selftest.py
```

覆盖索引、解析、搜索（关键字 / AND / 正则 / 仅异常）与统计。
样例日志不存在时会自动调用 `_make_mock.py` 生成，换台机器 clone 下来也能直接跑。

## 文件说明

| 文件 | 用途 |
|---|---|
| `LogParser.py` | 主程序（GUI + 数据层） |
| `ReleaseTool.py` | 打包 / 发布 / 自检的一体化 GUI |
| `build_args.py` | PyInstaller 构建参数（含 `--exclude-module` 体积优化） |
| `build_inproc.py` | 打包入口，规避 PyInstaller 子进程被杀的问题 |
| `check_version.py` | 版本一致性校验（`--fix` 可一键同步） |
| `publish_gitee.py` / `publish_github.py` | 发布到对应平台 |
| `publish_local.py` | 生成离线升级包（内网设备用，会校验 exe 与清单版本一致） |
| `verify_release.py` | 发布后自检线上产物 |
| `_find_python.bat` | 查找可用的 Python（要求带指定模块） |
| `_selftest.py` / `_make_mock.py` | 自测与样例数据生成 |
| `启动.bat` / `发布工具.bat` | 两个入口 |
| `app.ico` | 程序图标 |
| `version.txt` / `version.json` / `gitee-release/LogParser/version.json` / `github-release/version.json` | 版本与升级清单（由「升级版本…」同步，勿手改） |

> `build/`、`dist/`、`__pycache__`、`_mock_logs/` 都是生成物，已在 `.gitignore` 中排除，
> 可随时删除（`dist/` 里的 exe 是发布用的，删了需重新打包）。
